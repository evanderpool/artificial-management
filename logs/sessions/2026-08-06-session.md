### Shipped (uplink commit 3025270, pushed)
1. **Collections (schema v2):** `documents.collection`, UNIQUE(collection,
   path), per-collection corpus roots, scoped purges, in-place v1→v2
   migration (`uplink upgrade`, chunk ids + FTS preserved, idempotent).
   Default DB moved to `data/uplink.db`; `data/index.db` stays untouched as
   the eval regression corpus (fixtures depend on it) — EA docs are out of
   the web app.
2. **Localhost-only write rule:** upload + thumbs endpoints exist only on a
   loopback bind; wider binds are ask-only by construction. Hardened after
   review: X-Uplink header + Origin check (CSRF), Host validation with
   IP-literal allowance (DNS rebinding), negative Content-Length rejection,
   write serialization, byte-exact multipart parsing, upload overwrite
   refusal + cleanup on failed index.
3. **Industry corpora:** scripts/fetch_corpora.py (public-domain SEC 10-Ks /
   NIST pubs / CDC guidelines; corpora/ gitignored; SEC needs --contact at
   runtime — never committed). Indexed as finance/health/tech: 10 docs,
   4,661 chunks. New fixtures/industry-golden.jsonl (13 q):
   **hit@1 92% / MRR 0.923**, one vocabulary-mismatch miss, logged to eval
   history.
4. **Feedback loop:** query log with latency (data/query-log.jsonl), thumbs
   votes validated against the index (data/feedback.jsonl), `uplink promote`
   (last-vote-wins, idempotent) grows fixtures from real usage; `uplink
   export` emits docs+chunks JSONL (the future Supabase/vector path).

### Reviews (sequential, per protocol)
- **Logic review: 10 findings** — CRITICAL live CSRF corpus poisoning, DNS
  rebinding exfiltration, cap bypass via negative Content-Length, feedback

- **Code review: 8 findings** — write-lock contention, Host allowlist
  breaking wide binds + IPv6 bind failure, uncaught sqlite3.Error in CLI,
  snippet delimiter collision with Markdown brackets (now U+0001/U+0002),
  torn-line intolerance in history reader, error misattribution deleting
  good uploads, silent promote success on missing file, fetch IncompleteRead.
- All 18 fixed and pinned. **109 tests passing.** Regression corpus intact:
  hit@1 67% / hit@5 89% / MRR 0.769.

# Part 4 — Verifiable citations (Erick: "why can I not click on the sources")

Erick used Ask AI, got cited answers, and asked why the citations weren't
clickable. Correct catch and a real gap: citations named sources without any
way to open them, and the citations I had written were prose labels
("p. 21-22") rather than index coordinates, so they could not have anchored
even with a viewer.

## Built (uplink commit 6f6f832, pushed)
- `GET /api/doc?path=&collection=&seq=&start=&limit=` — serves a window of a
  document's chunks FROM THE INDEX (exact parameterized lookup), never the
  filesystem: no file-read surface to traverse, and it shows exactly what
  retrieval saw.
- Source panel in the web UI: citation chips and search-result paths are
  buttons; the cited chunk is centred and highlighted; earlier/later page
  through the whole document; close button; cleared on a new search.
- AGENT.md: citations MUST be index coordinates (path/section/seq/collection)
  copied verbatim from search JSON.

## Adversarial review of the doc surface — 5 findings, all fixed + pinned
1. HIGH: backward paging passed an absolute offset into `seq`, so the server
   re-centred and silently skipped limit/2 chunks per click (verified: 32-35,
   19-22, 9 unreachable on a 60-chunk doc). Now pages with explicit `start`;
   pinned by a test that walks a whole document and asserts zero gaps.
2. HIGH: a path in two collections resolved alphabetically — showing one
   collection's text as the source of a claim about another. Now 409 with the
   candidate collections (the only case where the feature could manufacture
   false evidence).
3. MEDIUM: citation without `seq` highlighted chunk #0 as "the cited passage"
   (Number(null)===0). Guarded with Number.isInteger.
4. MEDIUM: `seq` beyond int64 reached the SQLite bind → 500 + traceback.
5. LOW-MED: /api/doc returns untruncated text but wasn't logged. Reads now
   join searches in the query log, and the security posture docstring states
   plainly that reads are GETs — the localhost-only rule governs WRITES, not
   confidentiality. **Settle this before any Tailscale bind.**
